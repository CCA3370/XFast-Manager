# 飞行计划导入验收

导入入口只在首页。飞行计划页面负责查看、搜索、刷新和删除，不提供导入按钮或拖拽导入。

自动验证：

```powershell
npm test
npm run lint
npm run build
node scripts/verify-flight-plan-core.mjs
cargo test --locked --no-run
```

`verify-flight-plan-core.mjs` 直接执行生产文件管理代码的 Rust 测试，避开本机 Windows Tauri 测试程序在启动前报 `STATUS_ENTRYPOINT_NOT_FOUND` 的限制。

请在测试安装副本中准备多个合法 `.fms` 文件，至少包含同内容异名、同名不同内容和普通新文件。

| 操作 | 预期结果 |
| --- | --- |
| 从首页选择或拖入新计划 | 文件导入，显示成功数量；文件选择器可选择 `.fms` |
| 在飞行计划页面拖入计划 | 不导入；页面无导入按钮或拖拽大框；搜索、刷新、确认删除仍可用 |
| 重复导入同一计划，或用另一个名字导入相同内容 | 跳过并提示已有的文件名，不新增副本。BOM 和 Windows/Unix 换行差异不视为不同内容 |
| 导入同名但内容不同的计划 | 弹窗提供“替换 / 重命名 / 取消”；“下次不再提醒”初始不勾选，作出选择前原文件不变 |
| 选择重命名 | 原文件不变，新计划保存为 `名称.1.fms`，后续冲突递增为 `.2.fms`，并提示实际保存名 |
| 再次导入已重命名计划的内容 | 识别为重复并跳过，不继续生成新编号 |
| 选择替换 | 只有同名目标被新内容替换，其他计划不变，显示替换提示 |
| 取消，或按 Esc / 点击弹窗外部 | 当前文件不导入、不改名、不替换；同批其他文件继续处理。即使勾选过“不再提醒”，取消也不会保存默认行为 |
| 勾选“不再提醒”后选择重命名或替换 | 之后的同名不同内容按所选方式处理，不再弹窗；内容重复的计划仍跳过 |
| 在设置 → 安装偏好中改回“每次询问” | 下次同名不同内容再次弹窗；复选框仍默认不勾选 |
| 同一批包含重复、冲突、新计划 | 分别跳过、询问或导入，成功数量不包含重复与取消的文件；错误不应被计为成功 |
| 双击、三击普通页面文字与错误/日志正文 | 普通标签不被选中；错误弹窗、设置日志、活动详情、诊断证据可选中，输入框和可编辑区域正常编辑 |

关闭旧桌面程序后再启动更新的前后端，避免旧程序仍使用旧的导入返回格式。


## 计划详情验收

1. 导入包含 ADEP、ADES、CYCLE、SID/STAR 和多个航点的 1100 版计划。点击文件名展开摘要，确认出发点、目的地、航点数、距离和周期；再次点击收起。
2. 点击“详细信息”，查看可滚动弹窗。核对航路方向、航点标签，尝试放大、缩小、拖动和“适应航路”。关闭按钮及 Esc 均应关闭弹窗。
3. 核对高度剖面中的英尺数值；零值和缺失高度应显示未知，不能跨越未知区间连线。航路图仅表示文件航点，未展开 SID、STAR 或进近程序。
4. 在“航段距离”中核对相邻航点、大圆距离、累计距离、最长/最短/平均航段及航点表；未知坐标对应的距离不能显示为零或继续错误累计。
5. 在“文件内容”中选中复制全文，与原文件比较。检查、查看图表和导航查询均不得改变计划文件。
6. 用 v3 计划、跨越日期变更线的计划、坐标缺失/超出范围、声明数量不一致和错误文件头分别测试。有效信息应尽量显示，异常应显示解析提示；无法生成的图表不能编造数据。
7. 准备缺失坐标的命名定位点或导航台并打开详情，应自动读取导航数据且无读取按钮。确认使用当前安装的 Custom Data 或默认数据，并应用 user_fix/user_nav 覆盖。文件坐标保持不变；缺失坐标仅在唯一匹配时补全。同名多区域且无法确定的地点应继续留空。ARINC 424 覆盖和不可读数据会显示提示。
8. 更换 X-Plane 路径、刷新列表后再次打开详情，确认没有沿用上次安装或旧文件的缓存。航点表应位于独立分页；高度连续不变的区间只在中间标注一次，图表所有文字禁止选中；底图应离线显示海陆和国界。检查中文/英文、明暗主题、较小窗口下的滚动与表格。

格式依据：[X-Plane FMS 规范](https://developer.x-plane.com/article/flightplan-files-v11-fms-file-format/)、[X-Plane 导航数据层级](https://developer.x-plane.com/article/navdata-in-x-plane-11/)。此视图为文件检查工具，不执行完整飞行轨迹、程序航段或地形安全计算。
